# Road Wallet — product, security and release notes

Status: implementation candidate on `cursor/rigreceipts-pass0-3-v0.1-fc77`
(draft PR #8). **Feature-flagged OFF** (`road_wallet_enabled`). Not released.
Real-device validation, clean-bootstrap migration validation and two-user RLS
validation are still required (see "Evidence gaps").

## Purpose

Road Wallet is where a driver or small carrier keeps the reusable operational
documents they are asked for on the road and by brokers — registrations, cab
cards, insurance certificates, IFTA material, permits, authority evidence,
inspections, CDL and medical documents, W-9s, factoring notices, banking
paperwork and lease agreements — organized, available offline, and ready to
share deliberately.

RigReceipts = understand + organize + prepare. Road Wallet **stores and
organizes**; it does not determine whether a document is compliant, legally
valid, or accepted by any authority. That determination belongs to the issuing
agency. The app's only mention of compliance is the disclaimer that says so
(`ROAD_WALLET_DISCLAIMER`), and screen copy is tested to never claim otherwise.

## LoadDocument ≠ OperationalDocument

Load paperwork (BOL, POD, scale/lumper receipts) stays in
`src/domain/documents.ts` / `src/store/loadDocs.ts`, feeds the Paperwork grade
and the receipt/expense pipeline, and is captured through the Scan tab's OCR
flow. Road Wallet documents live in `src/domain/operationalDocuments.ts` /
`src/store/roadWallet.ts`, never feed grades or `expenses`, never go through
`parseReceipt`/`createCapture`/`document_scans`, and add no chips to
`SCAN_TYPES`. The Scan tab links to Road Wallet with one separate entry.

## Logical document vs immutable version

- **OperationalDocument** — the durable logical record: kind, subject, title,
  issuer/jurisdiction, issued/effective/expiration dates (`YYYY-MM-DD`), a
  masked reference (`****1234`), sensitivity, lifecycle (`ACTIVE` |
  `ARCHIVED`), `offlinePinned`, cloud status. Editable. Carries no file path.
- **DocumentVersion** — immutable exact-file evidence: id, document id, owner,
  version number, `supersedesVersionId`, file kind, MIME, extension, byte size,
  SHA-256, created time. Replacing a file never overwrites a version; it
  creates version N+1 superseding version N. A valid chain is exactly
  `1 → 2 → 3 …` (contiguous, each superseding its immediate predecessor); any
  break in persisted history truncates the chain so a corrupt entry can never
  become "current". The current version is the highest number in a valid chain.

Identifiers are 128-bit random opaque ids (16 CSPRNG bytes → 22-char
base64url) generated by `newSecureOpaqueId()`; the same id is used locally and
remotely. No filename, document number, name or other identifier is ever part
of an id or path.

## Account scope

Every document and version is bound to the account signed in when it was
created (`accountOwnerId`), or to `null` when created signed out. The wallet
shows only the current account's documents — or only unowned documents when
signed out. Unowned documents are never auto-claimed or auto-synced. Signing
out, switching accounts or changing plan never deletes local content; a user's
documents reappear when they sign back in.

## Free is local-first; Driver Pro adds cloud backup

- **Free / Road Log:** full local Road Wallet — add, edit, replace, archive,
  restore, offline readiness, expiry status. Files stay in app-private storage
  on the device.
- **Driver Pro and above (`cloudDocumentBackup`):** metadata and the current
  file are backed up to the user's private Supabase space (`documents` bucket
  at `{uid}/road-wallet/{documentId}/{versionId}.{ext}`; `operational_documents`
  / `document_versions` rows). Sync is authorized before every remote effect
  (signed in, entitled, content owner matches) and re-verifies the file's
  SHA-256 immediately before upload. "Backed up" appears only when **both**
  the metadata and the current version are synced. Authentication alone is
  never shown as backup.
- `cloudDocumentBackup` is a distinct capability from the receipt queue's
  `cloudBackup`, even though both begin at Driver Pro.

## Sensitivity classes and fixed kinds

`STANDARD`, `PERSONAL_SENSITIVE`, `FINANCIAL_SENSITIVE`. Known-sensitive kinds
have a **fixed** class enforced in domain validation, on metadata edits, in
persisted-state normalization and by a database CHECK:

| Kinds                                                | Class                           |
| ---------------------------------------------------- | ------------------------------- |
| CDL, MEDICAL_DOCUMENT, TWIC                          | PERSONAL_SENSITIVE              |
| W9, FACTORING_NOA, BANKING_DOCUMENT, LEASE_AGREEMENT | FINANCIAL_SENSITIVE             |
| everything else incl. CUSTOM                         | configurable (default STANDARD) |

The UI never offers a control implying these can be downgraded. Later system
Quick Present sets (Pass 2) use sensitivity as an exclusion boundary.

Only a masked reference is ever collected ("Last 4 of document number") and
stored as `****1234` via `maskReference()`. Full CDL/EIN/policy/account numbers
are never requested, stored, logged or sent to analytics.

## `offlinePinned` is a preference, not eviction

FINANCIAL_SENSITIVE documents default to `offlinePinned = false`; others to
`true`. In this candidate the pin is a future presentation/cache preference:
it never deletes or evicts a file, an imported document always keeps its
durable local copy, and nothing is auto-evicted after cloud upload.

## Local durable storage and integrity

Files are copied from the temporary picker/camera URI into app-private storage
(`Paths.document/road-wallet/{documentId}/{versionId}.{ext}` via
`expo-file-system`), verified (exists, non-zero, readable, content sniff
matches the declared kind, SHA-256 computed) and only then recorded. The
picker URI is never canonical. The original filename may inform the extension
but is never persisted.

**Current-runtime re-verification.** After the app restarts, no persisted
"ready" claim is trusted: every version rehydrates as `NOT_CACHED` with its
immutable expectations, and becomes `READY` only after
`reverifyDocumentFile()` succeeds in the current process (SHA-256 and kind
must match). The wallet re-verifies when it is focused, when a document detail
opens, and before any share. Missing → `File unavailable` (MISSING); changed
bytes → `File unavailable` (HASH_MISMATCH / CONTENT_MISMATCH). A changed file
never redefines a version; the remedy is to replace the document (new version).

## Archive, not delete

The product UI offers **Archive** and **Restore**, never physical delete.
Archived documents leave the active list but keep every version and can be
restored. Remote `document_versions` rows are append-only for the client
(SELECT + INSERT); `operational_documents` allows the owner SELECT / INSERT /
UPDATE but no client DELETE. Account deletion still removes everything through
`delete_current_account()` (owner cascade + private bucket sweep).

## Share / Export

Entitlement: `documentShareExport` — Driver Pro, Owner-Operator, Fleet Lite,
Lifetime. Free sees the action but is routed to the existing
`document_share_export` paywall trigger; Free keeps the full local wallet.

The only share path is `shareOperationalDocumentVersion()`, which: resolves
the current session; requires the document to be visible in it (and not
archived); resolves the exact version (default current); checks the tier;
re-verifies the physical file against the version's SHA-256 and kind and
records the result; checks the platform share capability; re-checks ownership
and entitlement immediately before the effect; then calls
`DocumentFileStore.share()`. A path existing is never enough. Nothing is
emailed, uploaded to a portal, or sent to a chosen recipient — the platform
share sheet is the only destination.

**Sensitive-share confirmation.** PERSONAL_SENSITIVE requires an explicit
acknowledgement ("This document may contain personal identity or medical
information…"); FINANCIAL_SENSITIVE requires the stronger one ("…tax,
banking, factoring or other financial information. Confirm that you want to
share this exact document."). The data layer refuses to share without the
matching confirmation signal, so the warning is not decorative.

## PDF

Supported: PDF import, private storage as PDF, exact metadata, byte-size and
`%PDF-` verification, SHA-256, Share/Export for entitled users.
**Deferred / BLOCKED:** inline PDF rendering and "Open in system viewer"
(`react-native-pdf` requires a native rebuild and device validation that this
candidate cannot provide; see `docs/REFINEMENT_CANDIDATE.md` C5). Document
Detail shows a truthful PDF file card; nothing is faked.

## Account export: metadata, not files

The JSON account export includes `operational_documents` and
`document_versions` metadata for the signed-in cloud account. It does **not**
include the binary image/PDF bytes, a portable archive of local files, or
device-only documents that were never cloud-synced. The Account & data screen
says so.

## Feature flags (all default OFF)

`road_wallet_enabled`, `quick_present_enabled`,
`document_expiry_alerts_enabled`, `carrier_profile_enabled`,
`carrier_packet_builder_enabled`, `carrier_packet_history_enabled`,
`multi_unit_documents_enabled`. Direct navigation to a Road Wallet route with
the flag off redirects to Reports. All tiers can see expiry status;
`documentExpiryAlerts` (Driver Pro+) is reserved for a later alert workflow
and is not implemented here.

## Analytics

No Road Wallet analytics are sent in this candidate. If added later, only
coarse events without title, issuer, jurisdiction, reference, truck/trailer,
paths, filenames, hashes, dates or contents.

## Evidence gaps (must close before release)

- **Real device:** file import/copy, `expo-crypto` digest and CSPRNG, camera,
  document picker and the share sheet have been validated against the SDK 57
  type surface and by tests — not on hardware.
- **Database:** clean Supabase bootstrap of migrations 00011–00014 and
  two-user RLS verification are not runnable in the implementation
  environment (statically parsed only).
- **Release gate (privacy/legal/store):** before enabling the flag —
  - Privacy Policy must describe operational-document storage, including
    potentially personal/medical and financial-sensitive documents;
  - App Store privacy disclosures must be reviewed;
  - Google Play Data Safety must be reviewed;
  - retention / delete / export behaviour (archive vs delete, metadata-only
    export, account deletion cascade) must be reviewed;
  - real-device storage and share behaviour must be tested.
